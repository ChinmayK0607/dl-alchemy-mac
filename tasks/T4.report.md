## Implementation and semantics

- `model.py`: reference stays unchanged by default. `no_prenorm` bypasses
  only block norms, retaining QK/final norms; `no_residuals` removes both
  skips; `no_mlp`/`no_attention` bypass the respective branch; `no_rope`
  retains QK normalization with identity rotations. Mixed residual leaves
  block zero unchanged, then computes `0.5*x_l + 0.5*x_(l-1) + A(x_l) +
  M(x_l+A(x_l))`, retaining autograd through both skip inputs. Dropout stays
  on attention probabilities and each computed branch, as in T3.
- `config.py`: variant validates and is included in the readable run name
  and full config digest. All variants retain every original parameter.
- `train_mlx.py`: MLX returns **zero** gradients for bypassed parameters.
  **Correction to the task's parenthetical:** PyTorch AdamW with `grad=None`
  skips the parameter, its moments **and weight decay**. Explicit zero
  PyTorch gradients would decay it. The port explicitly skips statically
  unused parameters to match the actual patched reference. Tests prove
  bitwise unchanged unused weights and zero moments across ten updates,
  and separately prove the None-versus-zero PyTorch behavior.
- Nonfinite micro-batch loss stops before an optimizer update or another
  micro-batch. The runner also detects nonfinite gradient norm/evaluation,
  writes the last metric, status `diverged`, and `final_val_loss=NaN`, then
  finishes W&B. Ordinary training exceptions produce an `error` summary.
  Throughput tokens count processed micro-batches, including an attempted
  divergent micro-batch; step counts include the final attempted update.
- `tracking.py`: project `dl-alchemy-popquiz`, default entity, question group
  q1/q2, variant/LR tags, full config including preset and source SHA256
  without invoking git, per-update loss/LR/pre-clip norm/tokens/tok/s/wall
  time, each validation loss, final/best loss/status/wall-time summaries.
  `wandb.init(dir=<run dir>)` uses a 20-second initialization timeout. Online
  failure falls back to offline; SDK errors preserve authoritative local
  metrics. `--wandb` defaults online; tests used real offline/disabled only.
  Online fallback was verified using a mocked SDK, with zero online runs.
- Weight saving defaults off, including the legacy array runner. Add
  `--save-weights` to save a final safetensors file. No new weights were left
  under `runs/T4-cpu/`; the T3 reload test opts in inside a temporary directory.
- `queue.py`: fresh sequential subprocesses, configurable timeout (default
  3600 s), process termination/reaping on timeout, error continuation,
  progress/ETA from observed worker durations, one append-only result per
  plan entry, and summary-based restart skipping. Timeouts/worker failures
  also get terminal summaries. To retry those, use a fresh output/results
  destination or archive the failed run directory. A killed worker cannot
  finish its W&B session; its queue status/log remain available locally.
- `popquiz_summary.py`: deduplicates restart records, excludes verification,
  ranks finite completed Q1 runs over its five-LR grid, computes Q2 using
  all shared reference LRs, and writes a run-status table and two PNGs.
  Divergence is explicitly non-finite; incomplete experiments remain missing.
  It rejects incompatible full recipe settings. Scientific output currently
  says 0/37 runs, with no ranking or ΔL, and plots explicitly show no results.
  Synthetic summary fixtures are temporary and never enter popquiz.jsonl.

JSON artifacts intentionally use Python's `NaN` spelling for the task's
nonfinite values; consumers must accept it (Python `json` does).

## Timing, best configuration and MFU

No new GPU experiment was possible in the sandbox. There is therefore **no
measured best T4 architecture/LR or local-preset GPU throughput/MFU**. The
operational local configuration remains d4/mp/micro 8/compile/chunk 1024;
its selection is inherited from T3, not proven optimal here.

For the unchanged Assignment 1 default, the code confirms d8 (eight layers,
width 512, eight heads × 64, intermediate 1792), RMSNorm, theta 500000 RoPE,
QK norm after RoPE, no biases, untied 4096 embeddings, context 1024, global
batch 64, AdamW LR 0.003, betas .9/.95, decay .1, clip 1, 1% warmup followed
by linear decay, mp, 600,000 sequences, 9,375 updates / 614.4M input tokens.
Default evaluation is every 94 updates plus final (100 complete passes).
Verified against reference `modeling.py`, `model_config.py`, `train.py`,
`optimizers.py`, `lr_schedules.py` and `MACHINE_LEARNING.md`; retained tests
also verify defaults and schedules against that code.

Historical coordinator measurements from `results/mlx_sweep.jsonl` below
are **reused T2/T3 data**, with ≥5 warmup and ≥20 synchronized timed updates,
full global batch 64×1024, compilation, CE chunk 1024, micro boundary,
no checkpointing. They predate T4's per-micro-batch finite-loss check and W&B.

```sh

  --precisions mp,bf16 --micro-batches 8,16 --compiled true \

```

Roofline: existing measured 4096³ GEMM achieved **2.6661 TFLOP/s fp32** and
**3.1060 TFLOP/s bf16**. FLOPs per update use
`F = 6*N*B*S + 12*L*B*S*S*d`, counting dense attention forward/backward
and approximating embedding work. N includes both embedding matrices;
B=64, S=1024. d8 gives 16.908816 TFLOP/update; d4 gives 3.145023.
MFU = `(F / seconds_per_step) / measured GEMM FLOP/s`, relative to achieved
GEMM, not vendor peak. No variant MFU is inferred using the full parameter
count when its branches are bypassed.

T3's unmeasured d4 projection is 15.2–20.2 min/local run, so a crude uniform
37-run allocation is **9.4–12.5 hours**, before accounting for bypassed
branches, divergence, tracking, startup and thermal behavior. It is a planning
range only; the queue's measured ETA should replace it. GPU final losses and
all scientific rankings remain pending coordinator execution.
