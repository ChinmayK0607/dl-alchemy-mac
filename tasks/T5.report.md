# T5 — portable Apple Silicon repository

Implemented the portable checkout workflow. A relocated copy successfully ran
`uv sync --locked` into an empty environment, then imported the MLX training
runner and dry-ran the queue without PyTorch or a course checkout. No git commands,
commits or pushes were performed; the coordinator must register the pinned
submodule before publishing this repository.

## Final commands

On a fresh Apple Silicon Mac with uv and Git installed, from the clone root:

```sh
scripts/setup.sh
scripts/check.sh
```

Setup initializes submodules, syncs Python 3.12 dependencies, downloads 100,000
seed-42 training sequences plus all validation rows, and prints MLX device info.
It resumes/reuses the same cache on repeat runs. `--num-train-sequences 600000`
selects the full A1 token budget; use `--data-dir data/a1-full` if a smaller
completed cache already exists. Setup uses `--merge-gap 0` so the full prefix
stays below the downloader's payload cap.

`scripts/check.sh` measures 4096-square fp32/bf16 matmuls and d8/mp/micro-batch 8
(compiled, CE chunk 1024, micro boundary, no checkpointing), then performs one
real-data smoke update plus full validation with W&B disabled. Benchmark timing
remains 5 warmup + 20 measured updates at global batch 64 × context 1024. Each
configuration and the smoke process have timeouts. Worker failures are recorded,
subsequent checks continue, and any failed check yields a nonzero script exit.
Artifacts go to `results/<hostname>/<UTC timestamp>/`; full run artifacts stay
under ignored `runs/`. Expect several minutes for the full d8 benchmark.

For parity/MPS tooling, use `scripts/setup.sh --parity` or
`uv sync --locked --extra parity`. A later default `uv sync` omits the optional
torch extra. No standalone safetensors or sentencepiece dependency is needed:
the code uses MLX's native safetensors API and pretokenized data.

## Behavior and portability

- `mlx_port/paths.py` is the only reference locator: explicit
  `DL_ALCHEMY_REFERENCE` > complete `reference/` > complete legacy sibling
  `../dl-alchemy-a1`. An invalid override fails instead of silently selecting
  another checkout. Errors identify the expected source commit and setup command.
  All MLX parity tests and the PyTorch port use this helper. Parity's old
  `--reference` flag is replaced by the common environment override.
- `run` and `queue` do not locate or import the reference. A relocated fixture
  with framework/reference imports blocked successfully loads runner configuration
  and dry-runs the queue. A separate fresh environment proves that torch is absent
  while runner imports and queue commands still work. Actual MLX training cannot
  be exercised in this sandbox, as detailed below.
- MLX allocation and wired caps now default to **75% of
  `mx.device_info()['max_recommended_working_set_size']`**, with no fixed GB default.
  `--memory-gb` overrides in GiB; `queue` and `sweep` forward it. Training configs
  and successful benchmark rows record the effective byte/GiB cap. CPU execution
  does not call Metal memory-limit APIs. This changes execution policy only.
- Normal pip MLX and its default device replace the removed custom CPU build.
  Tests accept `MLX_DEVICE=cpu` or `gpu`; selected CPU-only runner verification
  shapes remain explicitly CPU. Temporary directories are created automatically
  under ignored `.build/tmp`. No deleted library directory is required.
- `.gitignore` excludes virtual environments, data, runs, W&B files, bytecode,
  build/cache artifacts, all safetensors weights and the entire `logs/` directory.
  `results/` and `tasks/` remain project history. Machine-specific source paths and
  obsolete CPU-library commands were normalized in active docs and historical
  report reproduction commands. Historical result payloads remain historical.

## Inherited M4 measurements; no new GPU claim

For context, the existing `results/mlx_sweep.jsonl` contains these coordinator
measurements on the original M4. They predate T5 and used an explicit 14 GiB cap;
they do not validate the new automatic cap or predict M5 Pro performance. All
training rows use d8, global batch 64 × 1024, compilation, CE chunk 1024, micro
boundary and no checkpointing.

| Existing M4 configuration | tok/s | sec/step | Peak GiB | 9,375 steps + 100 evals, hours | MFU |
| --- | ---: | ---: | ---: | ---: | ---: |
| mp, micro-batch 16 | 6,475.5 | 10.1206 | 6.61 | 27.34 | 53.8% |
| mp, micro-batch 8 | 7,228.3 | 9.0666 | 3.84 | 24.65 | 60.0% |
| bf16 compute, micro-batch 16 | 7,307.7 | 8.9680 | 5.81 | 24.32 | 60.7% |
| bf16 compute, micro-batch 8 | 7,464.1 | 8.7801 | 3.60 | 23.85 | 62.0% |

Existing 4096-square matmul rooflines: fp32 **2.6661 TFLOP/s**, bf16
**3.1060 TFLOP/s**. Best inherited mp configuration is micro-batch 8, accumulation
8; fastest inherited alternate compute policy is bf16/micro-batch 8. Both retain
fp32 master weights and optimizer state. No new best configuration or measured
default-run time is available for the destination Mac.

The benchmark retains `F = 6*N*B*S + 12*L*B*S*S*d`, with N=34,612,736,
B=64, S=1024, L=8, d=512: **16.9088 TFLOP/update**. MFU is `(F/sec/step)`
divided by the measured matching matmul roofline, not a vendor peak. Projections
include 100 full validation passes, but exclude startup/compilation, data loading,
tracking/checkpoint I/O and sustained thermal effects. Small-shape parity history
does not establish full-run convergence for alternate precision policies.

The reference defaults were read and preserved: d8, width 512, 8 heads × 64,
SwiGLU 1792, RMSNorm, RoPE theta 500000, QK-norm after RoPE, bias-free projections,
untied 4096-vocabulary embeddings, context 1024, batch 64, AdamW LR 0.003 with
betas 0.9/0.95 and epsilon 1e-8, linear schedule with 1% warmup, mp precision,
600,000 sequences and 9,375 updates. No model/training-recipe changes were made.
