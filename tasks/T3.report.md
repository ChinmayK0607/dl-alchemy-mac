## Coordinator commands

Run from the workspace root **outside the sandbox**, using normal pip MLX.
The downloaded data is in `data/dclm/`.

```sh
# Full-context, real-data end-to-end smoke, including all 1000 validation rows.
.venv/bin/python -m mlx_port.run --preset smoke --device gpu

# Proposed local recipe: 320 updates, 20.97M tokens, four full evaluations.
.venv/bin/python -m mlx_port.run --preset local --device gpu

# P2-style 16-run grid; sequential isolated workers, bounded to 2 h each.
.venv/bin/python -m mlx_port.sweep --device gpu --preset local \
  --depths 4,5 --learning-rates 0.001,0.003 --schedules linear,cos \
  --dropouts 0,0.1 --timeout 7200 \
  --output-dir runs/p2-local --results results/T3_sweep.jsonl
MPLCONFIGDIR="$PWD/.build/matplotlib" .venv/bin/python -m mlx_port.plot_runs \
  --runs-dir runs/p2-local --output results/T3_comparison.png
```

Estimated smoke time: **76–94 seconds**. Estimated local time:
**15.2–20.2 minutes**. Estimated whole 16-run sweep: **6.7–12.5 hours**.
These are projections, not measurements of d4/d5 GPU runs; dropout can make
the sweep slower. Use a new `--run-name-suffix` or output directory for a
repeat: existing runs are protected against accidental overwrite.

For a custom sequence of trials, `--configs file.json` takes a JSON list of
TrainConfig override objects; `run --config file.json` takes one object.
CLI flags override that object, which overrides the preset.

## Data and exact ordering

Source: `kothasuhas/dl_alchemy_seq9p6m_context1024`, pinned revision
`8d066a12a614ce8641c661874960bf8567bf0f19`. Read the unmodified reference
`data.py` and `download_data.py`. The source manifest describes uint16 raw
files: 9,600,000 × 1024 training tokens and 1000 × 1024 validation tokens.
Its train file alone is 19,660,800,000 bytes, so downloading it whole is
incompatible with this task's budget.

The downloader obtains the exact **100,000-row global seed-42 prefix** using
verified HTTP byte ranges, coalescing gaps of at most eight rows. It records
original row indices in `data/dclm/train_ds42/source_rows.npy`. The reference
contract is `np.random.default_rng(seed).permutation(9600000)[:N]` after prefix
selection; shuffling an N-row local prefix would be incorrect. Pre-shuffled
caches with matching `data_seed` are returned unchanged by the reference.
Validation always uses the original 1000 rows, without shuffling.

Every range must return HTTP 206 and the exact Content-Range and byte count.
The full validation file and source metadata are checked against the
publisher's SHA256 digests. Local train and row-index hashes are recorded in
its completion metadata; the publisher's **whole 19.66 GB train hash cannot
verify a partial download**. A completion metadata file appears only after
all ranges finish. Checkpoints every 1000 ranges support restarting the same
download command. Other seeds require their own exact prefix cache; a
completed prefix cannot be extended in place (use another data directory).

Reproduce the download:

```sh
.venv/bin/python -m mlx_port.data --num-train-sequences 100000 --data-seed 42
```

## Recipe semantics and deliberate local changes

Supported unchanged TrainConfig defaults match the reference: d8, LR 0.003,
one epoch, global batch 64, num_micro_batches 1, num_evals 100, warmup 0.01,
weight decay 0.1, grad norm 1.0, dropout 0, data/model seeds 42, betas
(0.9, 0.95), linear schedule, mp precision and 600,000 train sequences.
`--preset reference` selects these. MLX compute-policy differences are those
already documented in T2: fp32 masters/moments, bf16 matmul/attention in mp,
fp32 loss; MLX RNG differs from PyTorch RNG.

| Preset | Model / parameters | Sequences / input tokens | Updates | Micro / global batch | Eval steps |
|---|---|---|---:|---|---|
| reference | d8 / 34,612,736 | 600000 / 614.4M | 9375 | 64 / 64 by default | every 94, plus final; 100 passes |
| local | d4 / 5,901,056 | 20480 / 20,971,520 | 320 | 8 / 64; accumulate 8 | 81, 162, 243, 320 |
| smoke | d4 / 5,901,056 | 1024 / 1,048,576 | 16 | 8 / 64; accumulate 8 | final only |

Both small presets retain context **1024**, batch **64**, the 4096-token
vocabulary, QK-norm after RoPE, untied embeddings and the reference optimizer.
Only model depth, token budget, evaluation frequency and accumulation change;
smoke also prints every step. Local has three warmup updates, with LR 0 on
the first update. Smoke rounds warmup down to zero, as the reference does.

`depth_model_config` matches reference d4..d9 (and supports d4..d18).
All reference schedules and aliases work: cos, linear/lin,
constant/const/flat, wsdFRACTION. Constant ignores warmup, matching the code.
Evaluation uses reference mean next-token NLL, weighting by B×(S−1) including
the final partial micro-batch; interval defaults to `(total_steps//num_evals)+1`
and always includes the final update. `--eval-interval` is an explicit override.
Training also preserves the reference's equal averaging of micro-batch means
if a non-divisible sequence count creates a partial training micro-batch.

Dropout applies to **attention probabilities and both residual branches**,
with inverted scaling. Nonzero probability dropout uses explicit attention
because MLX fused SDPA has no dropout argument. Evaluation disables all three
sites per layer. Compiled training threads MLX RNG state through each call,
so masks advance and model seeds reproduce a run. Dropout with activation
checkpointing is explicitly rejected because RNG replay is not implemented.

The local budget gives **3.55 input tokens per parameter**: enough for an
early-learning comparison, not a converged scaling-law result. A working
hypothesis is validation NLL around **4.5–5.8 nats**, below the measured
validation unigram entropy **6.8441 nats**. This expected range is **unverified**;
GPU final loss and LR/schedule/dropout separation must be measured. The
included `baseline` command computes a held-out baseline from training-token
unigrams rather than fitting on validation. Smoke is only a pipeline check.

## Timing, FLOPs and MFU

Formula: `F = 6*N*B*S + 12*L*B*S²*d`, including both vocabulary matrices in N,
B=64, S=1024. Dense masked attention is counted; embedding work is approximate.
The d8 update is **16.908816 TFLOP**; d4 is **3.145023 TFLOP**.

Existing coordinator measurements in `results/mlx_sweep.jsonl` (5 warmup,
20 synchronized timed updates/config):

| d8 precision | Micro batch | Input tok/s | s/update | Peak MLX GiB | Model TFLOP/s | MFU vs bf16 GEMM | Default 9375 updates incl. 100 evals |
|---|---:|---:|---:|---:|---:|---:|---:|
| mp | 16 | 6475.5 | 10.1206 | 6.61 | 1.6707 | 53.79% | 27.34 h |
| mp | 8 | 7228.3 | 9.0666 | 3.84 | 1.8650 | 60.04% | 24.65 h |
| bf16 | 16 | 7307.7 | 8.9680 | 5.81 | 1.8855 | 60.70% | 24.32 h |
| bf16 | 8 | 7464.1 | 8.7801 | 3.60 | 1.9258 | 62.00% | 23.85 h |

Each uses compiled micro steps, CE chunk 1024, micro evaluation boundary,
no activation checkpointing and full global batch 64×1024. The measured
4096³ matmul rooflines are **2.6661 TFLOP/s fp32** and **3.1060 TFLOP/s bf16**.
The fastest measured d8 setting is bf16/micro 8; local retains mp/micro 8
for the requested default precision. Neither is a measured best d4 setting.

Conservatively assume d4 achieves only **0.9–1.2 model TFLOP/s** (29.0–38.6%
of the measured bf16 GEMM roofline, well below measured d8's 60–62%). That
implies **18.75–25.01k input tok/s**, 2.62–3.49 s/update. Scale evaluation as
one-third of train FLOPs per sequence, include all four full validation
passes, and allow 20 seconds for startup/I/O: local totals **913–1211 s**.
Smoke totals **76–94 s**. For the 16-run d4/d5 grid, scale d5 by its FLOPs
and allow a 1.5–2.5× penalty for the eight explicit-attention dropout trials:
**6.7–12.5 h**. These assumptions may fail under thermal throttling or a less
favorable small-model kernel regime. `estimate_local.py` reproduces the
calculation in `results/T3_projections.json`.

Every run writes config/provenance, per-update loss/LR/pre-clip grad norm,
actual processed tokens, synchronized train tok/s, wall time and eval loss,
then summary/final evaluation and `final.safetensors`. Config hashes prevent
name collisions; no existing run is overwritten. The sweep captures worker
logs, kills timed-out workers and continues after OOM/nonzero exits. The
summary script writes a CSV and PNG; CPU verification runs are excluded by
default. Training tok/s includes data conversion and excludes evaluation;
wall time includes evaluation and final weight saving.

No W&B, module-RMS logging, checkpoint/resume, custom builders, SGD, tied
embeddings or disabling QK-norm are implemented in this runner. These are
outside the required knobs. Reduced-precision policies and initialization
are distribution/trajectory checked, not bit-identical across framework RNGs.
No GPU training was attempted inside the sandbox; there is no new measured
small-model GPU speed, final default-run convergence result or measured small
model MFU. Existing `mlx_port.bench` remains the bounded roofline/timing harness.
